# Parity with magpie

pansy rewrites [magpie](https://github.com/yetone/magpie) (Go, a Wails web
view) in Rust with an NSH 0.6.1 window. This page tracks what is ported. A
feature is ported when the gateway, the command line and the window all have
it, with tests.

## Ported

| :-- | :-- |

| Codex's free-form tools (`apply_patch`) on vendors without them | A stand-in function with one `input` string, turned back into `custom_tool_call` |
| Several keys per provider; the next takes over on 429, 402, 401/403, 5xx, quota messages | `route.rs` and `upstream.rs`: keys rest after a failure and are tried last: for the model asked after a limit, a timeout or a server's error, for every model when the key itself was refused or is out of credit. Not magpie's: a request a model turns away (a 400 and the like: its content, a part it can't take) goes on to the next model, past the same model's other keys, with nobody resting; the agent hears the first that turned it away if none answers. A connection that broke off or wasn't made is asked once more, a quarter of a second later, before its key rests and the request goes on |

| Models › Routing: the request on a stage (the agent, the gateway, the accounts lined up) and, while it is out, its data flowing on the wires; why the first was first, each try and what it answered, where the time went; the requests live or by day; each account's tries today | `trace.rs` keeps the last 60 in memory, never a prompt or a reply; each try goes on record in `usage/<day>.jsonl` (`tried`) for the days and Accounts and keys.
