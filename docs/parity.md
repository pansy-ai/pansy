# Parity with magpie

pansy rewrites [magpie](https://github.com/yetone/magpie) (Go, a Wails web
view) in Rust with an NSH 0.5.1 window. This page tracks what is ported. A
feature is ported when the gateway, the command line and the window all have
it, with tests.

## Ported

| magpie | pansy |
| :-- | :-- |
| One local gateway for every agent | `pansy-gateway`, `127.0.0.1:7267` (magpie: 3425, so both can run) |
| Anthropic, OpenAI Chat, OpenAI Responses, Gemini, translated between, streaming | `proto/` over one shape (`ir.rs`); same-protocol requests pass through untouched |
| Reasoning: Anthropic thinking, `reasoning_content`, Responses reasoning items, Gemini thoughts | Seals (signatures, encrypted reasoning, thought signatures) carry their vendor and go back only to it |
| Codex's free-form tools (`apply_patch`) on vendors without them | A stand-in function with one `input` string, turned back into `custom_tool_call` |
| Several keys per provider; the next takes over on 429, 402, 401/403, 5xx, quota messages | `route.rs` and `upstream.rs`: keys rest after a failure and are tried last |
| Errors before the answer begins move on; after, the agent hears them | `server.rs` waits for the first content event before it commits |
| Routing groups, nested; `order` and `rotate` | Also `usage` (least used since start); a group inside another routes its own way |
| Models › Routing: the request on a stage (the agent, the gateway, the accounts lined up) and, while it is out, its data flowing on the wires; why the first was first, each try and what it answered, where the time went; the requests live or by day; each account's tries today | `trace.rs` keeps the last 60 in memory, never a prompt or a reply; each try goes on record in `usage/<day>.jsonl` (`tried`) for the days and Accounts and keys. The window's gateway only: `pansy serve` has no window. The flow is animated values on a canvas, run natively: packets where magpie flew birds, and pansy's logo turning |
| Profiles: save, use, update, rename, delete | `pansy save` / `pansy use`; on the Agents page, chips whose ↻ and × ask a second click, and a chip's details with Apply and Rename |
| Agents: Claude Code, Codex, Gemini CLI, OpenCode, Qwen Code, Crush | Their configs edited in place (JSON/JSONC, TOML, `.env`), through symlinks; disconnecting puts a file back byte for byte (or removes one pansy made), or, when the user changed it since, each key pansy set |
| The Agents page: each agent's CLI version, Details with what was changed in its files, Disconnect and restore with what goes back, Move up/down and Hide, the rest folded under Show N more, Manage agents, Install another agent | `pansy-agents/src/cli.rs` reads a version from the install (npm's `package.json`, a folder named for it) and looks through mise's and asdf's shims without running them; the order and the hidden agents in `settings.json` (`agentOrder`, `agentsHidden`) |
| Provider presets and any compatible URL | magpie's 60 that pansy can serve (`presets.rs`), with their logos, notes, coding plans and regions (picked in the add dialog and the editor, each moving the endpoints, key page and plan's models), a vendor's global and China endpoints as one row, Azure's resource endpoint and a local server's address; custom providers in any of the four protocols. Ids from before are aliases |
| The Providers page: rows in the order they are tried in, the ones switched off folded, search by models served; the editor's Name, Advanced headers (with the vendor's), key header and proxy | A row's right click moves it (magpie also drags); a third-party Anthropic API gets the key in `x-api-key` and `Authorization`, and one that refuses both is asked with each alone and the one it takes kept, as magpie does |
| Model lists from the vendor | `GET /models` in the OpenAI, Anthropic and Gemini shapes; models added by hand stay |
| Work › Sessions: every session by the folder it ran in, with its model, messages, tokens and size; its details, the command that resumes it, its subagents, what was said in it, moved through prompt by prompt, to the top and the bottom, and exported as Markdown; found by its title, folder, id or words; Delete into a trash that restores | `pansy-agents/src/sessions/`: Claude Code's `projects/` (subagents' files counted in), Codex's rollouts (a thread it spawned listed under it) and OpenCode's `opencode.db` (1.2's tables, OpenCode 2's and what it hasn't copied yet; the older `storage/` files where there is no database; a subagent's session under its parent's), read only and kept in memory by size and time; OpenCode's are listed, not deleted, as it keeps its database open; the trash in `trash/sessions/`, 0700; a session written to in the last minute is not deleted; `pansy sessions` |
| Usage: requests and tokens by day, model and agent | `usage/<day>.jsonl`, Usage page, `pansy usage`; a request the agent cancelled is counted |
| Menu bar / tray app | NSH `Tray`; closing the window keeps the gateway running; the icon turns once as a pinwheel at a click, as magpie's bird flaps, and on and on while a request is out; the panel's mark turns as it opens |
| Self-update: a look a little after the start and every six hours, the Update pill in the title bar and the quick panel (download with its percent, wait for the gateway's requests to finish, restart), Settings › About › Updates with Check for updates | `desktop/ui/Update.tsx` over NSH's `nsh/updater`, from a signed feed on Cloudflare R2 (`nsh.json` `"updater"`, [release.md](release.md)); `packaging/build.sh` builds each system's archive and `packaging/publish.sh` puts a release there, from a tag (`.github/workflows/release.yml`). Where pansy can't replace itself, the pill opens the download. The pill's × hides it for three days; What's new shows a release's notes once after its update and from About (`desktop/ui/WhatsNew.tsx`). Not magpie's: a release of the window alone, a signed package of its TSX that pansy as installed restarts into (`runner/src/main.rs`) |
| The quick panel by the tray icon: a click opens it under the bar at the pointer, a click outside it, Escape or the icon again puts it away (Settings › Click the tray icon to opens the main window instead); its head's Update and tools; its tabs: Agents (a quiet line each, opened in place to connect the agent and pick its models), Usage (a period's totals, its days and its providers), Allowances (with a subscription signed in to) and Routing (today's count, the small stage of the agents that asked lately, pansy and where their requests went, and the latest requests with their speed); its foot's Profiles, status and Quit | `desktop/ui/Panel.tsx`, an NSH popup window; under Hyprland a window rule places it and a click bind announces clicks outside it (`desktop/native/src/panel.rs`, as magpie's), elsewhere the system places it and losing the focus closes it. Key balances aren't read, so Allowances shows the subscriptions alone; Usage's provider and computer pickers are not ported |
| Subscriptions' allowances: each account's windows (ChatGPT's 5 hours and week and its credits, Copilot's monthly premium requests, chat and completions, Code Assist's day of each model), the share used and when each renews; an account its vendor holds is passed over until it renews | `subscription/allowance.rs`: ChatGPT's `/wham/usage`, Copilot's `copilot_internal/user`, Code Assist's `retrieveUserQuota`, kept a minute in memory; the gateway reads them every 5 minutes and rests a held ChatGPT account until its window renews, and rests any account for as long as a 429 says (`resets_in_seconds`, `resets_at`, Google's `retryDelay`); `pansy limits`; the Usage page and the quick panel's Allowances tab |
| Share on the local network | `lan` with one gateway key (a header or Gemini's `?key=`), the model lists included |
| Subscriptions: ChatGPT (Codex), Copilot and Gemini Code Assist (Gemini CLI), the agent's own sign-in read where it is kept, more accounts signed in from the app (ChatGPT in the browser on Codex's port 1455 or by a device code, GitHub by a device code, Google in the browser), each subscription a provider whose accounts fail over like keys; a Code Assist account's Google Cloud project; Settings › Privacy turns reading the agents' sign-ins off | `pansy-core/src/subscription/`: Codex's `auth.json` (`CODEX_HOME`) and `logins.json` refreshed 5 minutes before they end or on a 401 and written back where read; Copilot's `apps.json`/`hosts.json` traded for a session; Gemini CLI's `~/.gemini/oauth_creds.json` (its own client's alone) refreshed in memory, its project from Code Assist's `loadCodeAssist`/`onboardUser`, the user's or `~/.gemini/.env`'s, its models from `retrieveUserQuota`; requests made as Codex CLI, Copilot Chat and Gemini CLI make them (Codex's instructions, nothing stored; Code Assist's envelope; a whole answer gathered from the stream); Copilot's models on the APIs its list names; `pansy accounts`, `pansy login`, `pansy logout`, `pansy accounts project`; the add sheet's Subscriptions and an editor's Accounts |
| Import from magpie, CC Switch, Alma, Claude Code, Codex and OpenCode: a tab per app, each entry's key masked, how one at an id in use or an address pansy has comes in (one more key, beside it, in its place), renamed in the picker; the Providers page's offer of what it finds, and Ignore until it changes | `pansy-agents/src/import/`: the apps read only (their databases opened read only), the keys read again on import and never handed to the window; Claude Code's relay read from what pansy put aside when it points at pansy; OpenCode's sign-ins read only when asked; ignored entries by a fingerprint in `settings.json` (`importIgnored`); `pansy import`. Import links: `pansy://import?…` opens the app on the link (nsh.json `schemes`, the runner on Linux; a `magpie://` link pasted reads the same), shown with the hosts the key goes to and added only on the yes, `pansy import [-y] <link>` (`import/link.rs`); a link's `icon`, `balance` and `catalog` are let be. Pasting a curl command or a vendor's environment lines (Paste…, the add sheet's search, a custom provider's URL or key) fills a custom provider as magpie's `curlOf` and `envOf` do (`import/paste.rs`, tested on magpie's vendor examples); the site's own icon is not fetched |
| English and Simplified Chinese | `desktop/ui/i18n.ts` |
| The window: sidebar, pages, model picker, light and dark | magpie's layout, sizes and palette, drawn with `nsh/base` (shadcn/ui's components) and shadcn's CSS variables in `desktop/nsh.json` |
| The sidebar hidden by the title bar's button (⌃⌘S, Ctrl+Shift+S), the pages then tabs in the title bar; the logo that moves as the window opens and under the pointer | `sidebar` in `settings.json`; it slides with `LayoutAnimation`, the pansy's petals flutter where magpie's bird flaps (`desktop/ui/Brand.tsx`). Dragging the sidebar's edge to widen it is not ported |
| Privacy masking: secrets, personal data, the user's words and rules; Mask, Warn or Block per kind; values that never mask | `pansy-mask` (magpie's rules, ported); the request is masked before it is routed, so passthrough and translation alike; placeholders put back in streamed and whole answers |
| Insights › Masking: what was kept from vendors, each request's steps and text before and after | `masking/<day>.jsonl` for 30 days without the values; the text in memory for the latest 100 requests; `pansy masking`, `pansy mask <text>` |
| Plugins: OpenCode auth plugins, pi packages, gateway middleware and request hooks, agent plugins; the community list, add, switch off, options, update, remove; sign-in to a plugin's provider; a middleware's routing for groups; magpie's plugins brought over | `pansy-plugins` on Bun 1.4.2 (downloaded and checked on first use): magpie's `host.js` and `pi.js` unchanged, pansy's `mw-host.js` for middleware and agents; Models › Plugins, `pansy plugin`; see [plugins.md](plugins.md). An agent's User-Agent mapped for a plugin's provider and Windows job objects are not ported |
| Settings' pages: General, Network and sharing, Privacy, and Find a setting | Sidebar pages, proxy Auto/Off/Custom, bare model ids, web pages that may call the gateway (others are refused), Try it |
| (pansy's own) One run of an agent on a model, its config not written; a project's file of models; usage by project | `pansy-agents/src/run.rs`: `pansy run [--model] <agent> […]` points one run at the gateway as each agent's manifest says ([agents.md](agents.md): Claude Code's `--settings`, Codex's `-c`, Gemini CLI's environment, OpenCode's `OPENCODE_CONFIG_CONTENT`; Qwen Code untried, Crush can't); `.pansy.toml`, found upward, holds model names alone and counts only once the user said yes to it as it is (`projects.json`); the run's key names its folder (`pansy_core::project`) and the gateway counts its requests under it (`project` in `usage/<day>.jsonl`); `pansy project`, `pansy usage`, the Usage page's By project. The Sessions page doesn't show a folder's file yet |
| (pansy's own) What connecting would write, before it is written | `pansy-agents/src/preview.rs`; `pansy <agent> <model> --show`; What it changes on the row of an agent not connected, with Connect |
| (pansy's own) What the gateway carries between protocols, as a page a test writes; what vendors' models refuse, as rules | [compat.md](compat.md), from `pansy-gateway/tests/compat.rs` over hand-written samples in the four protocols; `pansy-core/src/quirk.rs` and `quirks.toml` (the user's in pansy's folder), applied to translated requests alone; `pansy quirks`. The window doesn't list the rules |
| (pansy's own) Agents as manifests | `pansy-agents/agents/*.toml` and `manifest.rs`; the user's in `agents/` of pansy's folder ([agents.md](agents.md)); the six built in set what the code before them did (`agents/edits.golden`) |
| (pansy's own) A key's own proxy; keys in the system's key store | `manage::set_key_proxy`, `pansy provider key proxy`, the globe on a key's row; `pansy-core/src/keystore.rs` (`keyStore`: `system`), through `secret-tool` on Linux and `security` on macOS, not on Windows; Settings › Privacy › Keys. Tried against a folder standing in for the store, never a real keyring |
| (pansy's own) Settings › Diagnostics: whether the gateway answers or another program has its port, the providers and models, each agent's model still served and its config still on the gateway, pansy's private files; each problem's fix; a test request to a model picked, through the gateway as an agent's goes; an agent's own config restored for now, its model remembered to connect it again | `pansy-agents/src/doctor.rs` (codes the window and the command line word each), `pause`/`resume` in `pansy-agents` (`paused` in `agents.json`); `pansy doctor`, `pansy test [provider/model]`, `pansy pause <agent>\|all`, `pansy resume <agent>\|all`; `desktop/ui/Diagnostics.tsx` |
